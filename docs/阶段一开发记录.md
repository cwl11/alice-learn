# 第一阶段开发记录

> 日期：2026-09-04  
> 范围：从零搭到可本地运行的 MVP，并把登录/注册/主页视觉统一

配套需求见 [需求准备文档.md](./需求准备文档.md)。本地启动见仓库根目录 [README.md](../README.md)。

---

## 1. 本阶段目标

把「注册登录 → 写作题库 → 作文提交 → AI 范文 / 批改 → 词汇 / 阅读」最小链路做出来，方便后续继续加听力、口语。

本阶段结束时：

- 前后端都能在本机启动
- 数据库由 Flyway 自动建表并灌种子数据
- 没有 DeepSeek Key 时，除 AI 外功能仍可用

---

## 2. 已落地的功能

### 用户

- 注册（用户名、邮箱、密码、目标分数）
- JWT 登录；未登录跳转登录页
- 个人中心查看资料和作文记录

### 写作

- Task 1 / Task 2 题库分页、筛选
- 草稿保存、字数统计、按题型校验最低词数后提交
- AI 流式生成范文（SSE）
- AI 按 TA / CC / LR / GRA 打分并给出逐句建议，报告页用雷达图展示

### 词汇

- 约 300 个 AWL 高频词（音标、释义、例句、话题分类）
- 生词本、简化间隔重复记忆卡片

### 阅读

- 3 篇短文 + 选择题 / 判断 / 填空
- 提交后自动判分并显示解析

## 3. 技术实现摘要

| 部分 | 实际采用 |
|------|----------|
| 后端 | Java 21、Spring Boot 3.4.5、Maven |
| ORM | MyBatis-Plus 3.5.9 |
| 认证 | Spring Security + JWT（JJWT 0.12） |
| 文档 | Knife4j `/doc.html`（已关掉 `springdoc.override-with-generic-response`，避免 Boot 3.4 冲突） |
| 迁移 | Flyway：`V1` 表结构，`V2` 写作题，`V3` 词库，`V4` 阅读 |
| AI | Spring AI OpenAI 兼容接口，指向 `https://api.deepseek.com`，Key 用环境变量 `DEEPSEEK_API_KEY` |
| 前端 | Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、ECharts、Axios |
| 数据库 | 本机 MySQL 8，库名 `alice_learn` |

目录：

```
alice-learn/
├── docs/                 需求与阶段记录
├── backend/              Spring Boot
└── frontend/             Vue 3
```

核心接口前缀均为 `/api`，统一返回 `{ code, message, data }`。写作范文接口为 `POST /api/writing/essays/{id}/sample`（SSE）。

---

## 4. 数据库与种子数据

首次启动后端时，JDBC 会尝试创建 `alice_learn`，Flyway 再建表。

种子数据规模：

- 写作题 15 道
- 词汇 302 个（Academic Word List 子集，不爬商业词库）
- 阅读 3 篇、每篇 5 题

网站用户存在表 `user` 中，和 MySQL 的 `root` 账号不是一回事。密码使用 BCrypt。

---

## 5. 界面（本阶段后半段）

登录、注册、登录后主页使用同一套「墨水 + 暖纸」风格：

- 深色品牌区：`#16132b` / `#1e1b4b`，强调色 `#c45c26`
- 内容区暖纸：`#f4efe6`
- 标题字体 Fraunces，正文 DM Sans
- 登录注册为左右分栏：左侧约 38%，右侧 `1fr` 铺满窗口
- 宽屏下用户名/密码（或用户名/邮箱）并排；窄于 960px 改为上下排布
- 顶栏与主页英雄区沿用登录页的深色渐变

## 6. 本地如何运行

1. MySQL 已启动（开发环境账号见 README）
2. `backend`：`mvn spring-boot:run`（可选设置 `DEEPSEEK_API_KEY`）
3. `frontend`：`npm install` 后 `npm run dev`
4. 浏览器打开 http://localhost:5173 ，先注册再登录
5. 接口文档：http://localhost:8080/doc.html

---

## 7. 已知限制与下一阶段建议

- AI 范文和批改依赖 DeepSeek；未配置 Key 时会返回明确错误，不会拖垮其它模块
- 听力、口语、后台运营、支付未做
- 词库目前约 300 词，后续可继续按话题扩充
- 作文目前每次保存都新建一条记录，尚未做「同一草稿多次更新」
- 雷达图在批改页按需加载 ECharts

建议下一阶段优先：

1. 配置并验证 DeepSeek 全流程（范文流式 + 批改落库）
2. 草稿更新、作文明细与题库的关联展示
3. 把写作 / 词汇 / 阅读内页也统一成主页同一套视觉
4. 补充后端集成测试与基础 E2E
