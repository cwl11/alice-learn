## 1.1 配置外置（.env）

`application.yml` 里不再出现任何真实密码 / 密钥，改为：

```yaml
spring:
  config:
    import:
      - optional:file:.env[.properties]
      - optional:file:.env.local[.properties]
```

- `backend/.env`：**提交到 Git** 的模板，只放非敏感默认值（host、port、model…）和空占位（`DB_PASSWORD=`、`JWT_SECRET=`）
- `backend/.env.local`：**已 gitignore**，放真实值，逐项覆盖 `.env`
- 优先级：`.env` < `.env.local` < OS 环境变量，所以 CI / 服务器直接 `export` 即可，不需要文件
- 路径相对后端工作目录，`mvn spring-boot:run` 与 IDE 默认工作目录（模块根）都能读到
- 用 Spring Boot 原生 `spring.config.import`，`[.properties]` 是无扩展名文件的格式提示，不引入 dotenv 依赖

可配项：`SERVER_PORT`、`DB_HOST/PORT/NAME/USERNAME/PASSWORD`、`AI_BASE_URL/MODEL/TEMPERATURE`、`DEEPSEEK_API_KEY`、`JWT_SECRET/EXPIRE_HOURS`、`CORS_ALLOWED_ORIGINS`。`DB_PASSWORD` 与 `JWT_SECRET` 故意不给默认值：缺了会在启动时报 `Could not resolve placeholder`，而不是带着弱密钥悄悄跑起来。

## 1.2 DeepSeek 接通与模型切换

首次用真实 Key 跑通了范文 + 批改全流程，过程中修正了三处：

| 问题 | 处理 |
|------|------|
| `deepseek-chat` 别名已于 2026-07-24 下线，调用直接报错 | 模型改为 `deepseek-v4-flash`（现役最便宜：约 $0.14–0.22 / M 输入，$0.28–0.66 / M 输出，分峰谷计价）；`AI_MODEL` 可切 `deepseek-v4-pro` |
| V4 默认开 thinking：推理 token 按输出价计费，且流式要等推理结束才吐正文 | Spring AI 升到 1.1.2（`OpenAiChatOptions.extraBody` 是 1.1 才有），`AppConfig` 默认传 `thinking.type=disabled`，`AI_THINKING=true` 可开 |
| 范文 SSE 接口抛业务异常时，`Accept: text/event-stream` 接不到 JSON 错误，前端只见笼统「生成失败」 | 控制器把 `BusinessException` 转成 `event: error`；`AiWritingService.describeAiError` 把 401/402/429/模型不存在翻译成人话；前端 `stream.ts` 解析 `event:`，出错抛出而不是把错误文本当范文拼进去 |
| 前端 `data:\s?` 正则多吃一个空格，token 常以空格开头 → 单词粘连 | 只截掉 `data:` 五个字符 |
| 范文生成完按钮一直转圈：`SseEmitter` 完成时容器以 ASYNC 类型重新派发请求，JWT 过滤器（`OncePerRequestFilter`）默认跳过 ASYNC，授权过滤器报 `Access Denied`，响应被异常收尾；curl 能容忍，浏览器 fetch 经 Vite 代理后 `reader.read()` 永不结束 | `SecurityConfig` 加 `dispatcherTypeMatchers(ASYNC, ERROR).permitAll()`；流完成回调里落库/记日志放进 try/finally，保证 `emitter.complete()` 一定执行 |

另加 `max-tokens: 2000` 上限防失控。实测（`deepseek-v4-flash`，非 thinking）：范文 360 词、420 个流式片段、6 s；批改返回四维分 + 5 条逐句建议 + 改进段落、8 s；一次范文 + 一次批改约 2300 token，不到 0.01 元。

## 2. 数据库变更：`V5__phase2_history_and_constraints.sql`

```sql
ALTER TABLE `user` ADD UNIQUE KEY uk_user_email (email);
ALTER TABLE essay ADD COLUMN sample_essay MEDIUMTEXT NULL;
CREATE TABLE reading_attempt (id, user_id, passage_id, total, correct_count, time_spent_sec, created_at);
ALTER TABLE user_answer ADD COLUMN attempt_id BIGINT NULL;
```

- `reading_attempt`：一次提交 = 一条记录，是阅读历史的主表
- `user_answer.attempt_id`：把逐题答案挂到某次提交上，回顾模式据此还原
- `essay.sample_essay`：SSE 流式生成的范文在结束时整体落库（之前只在前端内存里，刷新即丢）
- 执行前确认过本地库 `user.email` 无重复，`UNIQUE` 可直接加

## 3. 后端接口变化

### 写作 `/api/writing`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/tasks/{id}/draft` | 该题目下我最近一篇**未批改**的作文（草稿或已提交），编辑页用它回填；无则 `data: null` |
| POST | `/essays` | 新建（不变） |
| PUT | `/essays/{id}` | **新增**：更新同一篇；`REVIEWED` 状态冻结不可改 |
| DELETE | `/essays/{id}` | **新增**：删除作文及其批改记录 |
| GET | `/essays/{id}` | 详情新增 `sampleEssay`、`updatedAt` |

### 阅读 `/api/reading`

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/answers` | 请求体新增必填 `passageId`、可选 `timeSpentSec`；每个 `answers[].questionId`/`answer` 均 `@NotNull`；服务端校验题目属于该文章、不重复；返回新增 `attemptId` |
| GET | `/attempts/{id}` | **新增**：某次练习详情（含每题作答、正确答案、解析），只能看自己的 |

### 个人中心 `/api/me`

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/essays` | 返回类型改为 `EssaySummaryResponse`（含 `taskTitle`、`taskType`、`overallScore`、`updatedAt`），新增 `status` 筛选参数 |
| GET | `/reading` | **新增**：阅读练习记录分页 |

### 认证

- 注册：邮箱 trim + 小写后查重，重复返回「该邮箱已被注册」；并发下靠唯一键兜底捕获 `DuplicateKeyException`
- JWT 过滤器不再静默吞掉异常，而是把原因挂到 request attribute，由 `authenticationEntryPoint` 返回：
  - `{"code":40101,"message":"登录已过期，请重新登录"}`
  - `{"code":40102,"message":"登录凭证无效，请重新登录"}`
  - `{"code":401,"message":"请先登录"}`（无 token）
- 公开接口（登录 / 注册）即使带着过期 token 也照常放行，避免"过期后连登录都 401"

## 4. 前端变化

### 新增

- `components/AsyncState.vue`：loading → 骨架屏、error → 失败 + 重试按钮、empty → 空态 + 可选操作，其余渲染 slot。所有列表 / 详情页都换成了它
- `utils/format.ts`：时间、用时、作文状态文案与 tag 颜色

### 写作编辑页 `WritingEditorView`

- 进入题目时自动拉取最近草稿回填；也支持 `?essayId=` 从个人中心「继续写」进入
- 已有 `essayId` 时保存走 PUT，不再重复建行；提供「新开一篇」
- 已批改的作文进入编辑页会提示并自动新开
- 有未保存修改时离开页面弹确认
- 范文生成前若有改动先自动保存；生成后的范文随作文持久化，下次进入直接显示

### 报告页 `EssayReviewView`

- 显示同题 AI 范文（`essay.sampleEssay`）和批改给出的「改进示例段落」
- 增加四维分数条、批改时间；草稿状态禁用批改按钮并说明
- 顶部「继续修改」「删除」；批改结果为空时显示占位说明

### 个人中心 `ProfileView`

- 改为 Tab：作文记录 / 阅读记录
- 作文表：题目 + 类型 tag、词数、状态 tag、总分、最近更新、按状态筛选、分页、继续写 / 看报告 / 删除
- 阅读表：文章 + 难度、得分（按正确率着色）、用时、时间、看解析 / 再练一次

### 阅读练习页 `ReadingPracticeView`

- 计时器（进入即开始，提交时把用时一并上报）
- 提交前有未答题会提示；提交后表单只读，显示得分、「查看记录」「再练一次」
- `?attemptId=` 进入回顾模式：还原当时作答与判分，不计时

### 其它

- `ReadingListView` / `VocabView` / `VocabReviewView` / `WritingListView`：统一接入 `AsyncState`；阅读列表加分页；词库显示生词本熟悉度；加入 / 移出生词本改为局部更新并带 loading
- `api/http.ts`：401 时按 `40101 / 40102` 给出不同提示，并把当前路径放进 `?redirect=` 便于登录后回跳；超时 / 断网给出明确文案
- `styles.css`：删掉重复的 `.card` 定义，`.muted` 提到全局
- `tsconfig.node.json` 增加 `"types": ["node"]`，`package.json` 补 `@types/node`，`npm run build` 恢复可用

## 5. 验证方式

- 后端：`mvn test` 通过（既有 6 个单测）
- 接口：本地起服务后按下面顺序手工 / 脚本走了一遍，全部符合预期
  1. 登录 → 用已存在邮箱注册 → 拒绝
  2. 无 token / 坏 token 访问 `/auth/me` → `401` / `40102`；带坏 token 登录仍成功
  3. 新建草稿 → `/tasks/1/draft` 能取到 → PUT 更新 id 不变 → 字数不足提交被拒 → 达标后提交为 `SUBMITTED`
  4. `/me/essays` 有题目标题与状态，`status` 筛选生效
  5. 阅读提交：题目不属于该文章 / 缺 `passageId` / `answer` 为 null 均 400；正常提交返回 `attemptId`，`/me/reading` 与 `/reading/attempts/{id}` 能查到
  6. 另一个用户访问他人 attempt / 删除他人作文 → 403；删除自己的作文后详情 404
- 前端：`vue-tsc` 无报错，`npm run build` 成功

## 6. 已知事项

- `application.yml` 开启了 `default-property-inclusion: non_null`，因此 `sampleEssay` 为空时字段不会出现在 JSON 里，前端类型已按可选处理
- 阅读历史只记录"提交"这一动作；中途离开不会留记录
- 计时器只在前端计时，用时是自报值，不做服务端校验（学习工具够用）
- 删除作文是物理删除，没有软删；如需找回需要在第二批加 `deleted_at`
